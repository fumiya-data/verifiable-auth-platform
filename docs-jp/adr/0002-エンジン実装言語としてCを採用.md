# ADR 0002: エンジン実装層に C を採用する

この文書は [`../../docs/adr/0002-engine-implementation-language.md`](../../docs/adr/0002-engine-implementation-language.md) の日本語版です。

## ステータス

承認済み

## 背景

engine は、認証状態機械を実行可能な形で実現する層です。システム寄りの実装に適しており、
データ構造、メモリ、実行時挙動に対する明示的な制御に近いものである必要があります。

Rust は安全性や ergonomics の点ではより望ましい面を持ちます。しかしこのプロジェクトの目的の一つは、
低レベルシステム実装の強みと本質的な難しさを実地に理解することです。C言語はメモリ処理、データ表現、
明示的な状態遷移制御といった関心事を直接表面化させる言語です。したがって、今回は意図的にC言語で実装します。

## 決定

engine 実装層には `C` を採用し、現代的な `C23` スタイルで記述します。

## 根拠

- engine はシステム指向コンポーネントであり、C はシステムプログラミングと親和性が高いです。
- Rust は信頼できる代替案ですが、本プロジェクトでは低レベル実装上の関心事に
  より直接向き合うため、意図的に C を選択します。
- これには、メモリ処理、データ表現、engine 境界における明示的な状態遷移制御への
  実践的な露出が含まれます。
- プロジェクトは、その低レベル実装モデルと、純粋にレガシーな C として扱わない
  規律ある現代的コーディングスタイルとを組み合わせることを狙っています。
- この選択は、`C23` 指向の実践を含む modern C の流儀で作業したいという
  意図に基づいています。

## 帰結

- engine は機械モデルに近い位置を保ち、明示的な状態遷移実装に適したままです。
- より安全で ergonomic な言語、たとえば Rust を使う場合に比べて
  大きな実装負荷を受け入れることになります。
- C 層を保守可能かつ安全に保つため、コードベース側で明確な規約を
  強制する必要があります。
- その代わり、低レベルシステム実装の強みと難しさを直接経験できる
  engine 層が得られます。
