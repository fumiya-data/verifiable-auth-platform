# ADR 0003: Go TUI を薄い運用ラッパーとして保つ

この文書は [`../../docs/adr/0003-thin-tui-boundary.md`](../../docs/adr/0003-thin-tui-boundary.md) の日本語版です。

## ステータス

承認済み

## 背景

このプロジェクトは、第一義的には UI デザインのためのものではありません。
中心となるテーマは、仕様、実装、テスト、観測可能性にわたって認証挙動を検証できることです。
したがって UI は運用を支援しつつも、認証ロジックの第二実装になってはいけません。

## 決定

`Bubble Tea` で構築した `Go` TUI を採用し、engine 契約の薄いラッパーとして保ちます。

## 根拠

- UI に必要なのは engine を包み、操作を公開することだけであり、
  ドメイン側のロジックを抱える必要はありません。
- TUI を薄く保つことにより、interaction と authentication semantics の
  アーキテクチャ境界を維持できます。
- Bubble Teaフレームワークは、洗練されたターミナル UI を比較的簡潔に構築する手段を提供します。
- UI 開発をプロジェクトの中心となる関心事にしなくても、十分見た目の整ったインターフェースを実現できます。

## 帰結

- 中核の認証規則が UI 層の外側にとどまり、UI層には侵入しないことから、TUI は別のものに置き換え可能です。
- engine 契約が安定している限り、UI 挙動は独立に進化できます。
- presentation code へ business logic が漏れ出すリスクを低減できます。
