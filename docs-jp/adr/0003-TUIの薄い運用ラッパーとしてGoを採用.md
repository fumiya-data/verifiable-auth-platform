# ADR 0003: Go TUI を薄い運用ラッパーとして保つ

この文書は [`../../docs/adr/0003-thin-tui-boundary.md`](../../docs/adr/0003-thin-tui-boundary.md) の日本語版です。

## ステータス

承認済み

## コンテキスト

このプロジェクトは、第一義的には UI デザインのためのものではありません。
中心テーマは、仕様、実装、テスト、観測可能性をまたいだ認証挙動の検証可能性です。

したがって UI は運用を支援しつつも、認証ロジックの第二実装になってはいけません。

## 決定

`Bubble Tea` で構築した `Go` TUI を使用し、engine 契約の薄いラッパーとして保ちます。

## 根拠

- UI に必要なのは engine を包み、操作を公開することだけであり、
  domain logic を抱える必要はありません。
- TUI を薄く保つことで、interaction と authentication semantics の
  アーキテクチャ境界を維持できます。
- Bubble Tea は、洗練されたターミナル UI を比較的簡潔に構築する手段を提供します。
- UI 開発をプロジェクトの中心関心にしなくても、十分に整った見た目の
  インターフェースを実現できます。

## 帰結

- 中核の認証規則が UI 層の外にとどまるため、TUI は置き換え可能なままです。
- engine 契約が安定している限り、UI 挙動は独立に進化できます。
- presentation code へ business logic が漏れ出すリスクを低減できます。
