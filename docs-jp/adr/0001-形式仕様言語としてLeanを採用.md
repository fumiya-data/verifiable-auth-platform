# ADR 0001: 形式仕様層に Lean を採用する

この文書は [`../../docs/adr/0001-formal-specification-language.md`](../../docs/adr/0001-formal-specification-language.md) の日本語版です。

## ステータス

承認済み

## コンテキスト

このプロジェクトは、機能の広さよりも検証可能性を中心に据えています。
主たる価値は認証挙動を実装することだけでなく、認証の意味論を明示し、
分析可能かつ説明可能なものにすることです。

その目標のために、実装に適しているだけでなく、形式的推論に適した
言語とツールチェインが必要です。

## 決定

形式仕様層には `Lean` を使用します。

## 根拠

- 本プロジェクトは、実行系をできるだけ早く作ることよりも、
  認証意味論を明確にすることに高い価値を置いています。
- `verifiable-auth-platform` という名前自体が、検証を第一級の性質として
  優先する意図を表しています。
- Lean は形式仕様と形式検証に適しています。
- Lean は、実装詳細に依存せずに、不変条件、状態遷移、正しさ関連の性質を
  精密に記述できる媒体を提供します。

## 帰結

- 仕様層は、システム全体に対する意味論的参照点として機能できます。
- 不変条件と遷移規則を、engine から独立に明示・レビューできます。
- 形式モデルを保守するコストを引き受ける一方で、
  トレーサビリティと正しさに対するより強い土台を得ます。
